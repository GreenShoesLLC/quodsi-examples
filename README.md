# Quodsi example models

Worked discrete-event simulation models you can open directly in Quodsi's
drawio editor — no download, no account, no setup.

## Opening an example

In Quodsi drawio: **Quodsi → Open Example Model…**, then pick one. Examples
are grouped: **Learn** teaches one Quodsi feature at a time; **Industries**
shows complete models from a field.

Every drawio example is also a plain link you can share:

```
https://dev-drawio.quodsi.com/#U<url-encoded-raw-url-of-the-model>
```

Opening a model this way loads it as an unsaved file. Edit freely — you are
working on your own copy and cannot affect what's published here.

## Repository layout

```
groups.json                      the sections and groups, in display order
manifest.json                    GENERATED — the catalog the picker reads
<section>/<group>/<slug>/
  example.json                   title, summary, teaches, order
  README.md                      what it shows and what to try
  model.drawio                   opens in the drawio picker
  model.json                     a Quodsi model document for the quodsi CLI
scripts/
  build-manifest.mjs             regenerates manifest.json and the table above
  validate.mjs                   the checks CI runs
  publish.mjs                    prepares a drawio file saved from the app
```

The folder path is the classification: an example's section and group are
where its folder sits. An example needs `model.drawio`, `model.json` or both;
only examples with `model.drawio` appear in the picker.

## Rules

CI enforces these on every push (`scripts/validate.mjs` and
`scripts/build-manifest.mjs --check`):

- **Folders are `<section>/<group>/<slug>`**, with the section and group
  declared in `groups.json` and the slug unique across the repo (lowercase
  letters, digits and single dashes).
- **Every example has `example.json` and `README.md`.**
- **No `quodsiDocumentId` in a `model.drawio`.** That attribute binds a
  diagram to one Quodsi model record; if a published example carried one,
  every user who opened it would overwrite each other's work.
- **`model.drawio` is stored uncompressed**, so it can be reviewed, diffed
  and checked.
- **`manifest.json` and the table above are up to date.** CI runs
  `node scripts/build-manifest.mjs --check`.

## Contributing an example

The full walkthrough is in [CONTRIBUTING.md](CONTRIBUTING.md). In short:

1. Build it in Quodsi drawio, run **Convert Diagram to Model**, run it, and
   save it to your device.
2. `node scripts/publish.mjs <saved-file> <section>/<group>/<slug>`.
3. Fill in `example.json` and write the folder's `README.md`.
4. `node scripts/build-manifest.mjs`, then `node scripts/validate.mjs`.
5. Push to a branch and open a pull request into `dev`.

A new group goes in `groups.json` in the same pull request.

## Branches

Each Quodsi environment reads its own branch of this repo:

| Branch | Read by |
|---|---|
| `dev` | the dev environment (dev-drawio.quodsi.com) |
| `test` | the test environment (test-drawio.quodsi.com) |
| `main` | local builds, and production when it exists |

New examples land on `dev` first and promote `dev` → `test` → `main`,
mirroring how the Quodsi engine itself is promoted.
